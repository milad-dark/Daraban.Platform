## ۱. خلاصه وضعیت

| حوزه | وضعیت فعلی |
|---|---|
| هسته سامانه (هویت، دارایی‌ها، میز خدمت، مالی، دانش، نرم‌افزار، کشف، سرشماری) | پیاده‌سازی‌شده (بک‌اند) |
| چارچوب افزونه (Task 7.5 — Plugins) | پیاده‌سازی‌شده: بارگذاری ایزوله با AssemblyLoadContext، مهاجرت در شمای plugins_{id}، رابط کاربری مدیریت افزونه |

| استقرار | پوشش ناقص وورکرها در Docker Compose، بدون HTTPS و CI/CD |

## ۲. ماژول‌های ناقص

### ۲-۱. ماژول خودکارسازی (Automation)

- موجودیت‌ها و جدول‌های دامنه خودکارسازی (قانون، سناریو، اجرا) تعریف نشده‌اند؛
- کنترلر/API برای مدیریت قوانین خودکارسازی وجود ندارد؛
- وورکر ارزیابی قوانین (RuleEvaluator) وجود دارد ولی منطق عملیاتی آن به موجودیت‌ها متصل نشده است؛
- رابط کاربری برای تعریف قوانین و مشاهده اجراها وجود ندارد.

### ۲-۲. ماژول اطلاع‌رسانی (Notifications)

- موجودیت‌ها (قالب پیام، مقصد، تاریخچه ارسال) تعریف نشده‌اند؛
- کانال‌های ارسال واقعی (ایمیل، پیامک، اعلان درون‌برنامه‌ای) پیاده‌سازی نشده‌اند؛
- وورکر توزیع اطلاع‌رسانی وجود دارد اما مصرف‌کننده رویدادها هنوز به کانال واقعی متصل نیست؛
- ارسال ایمیل تأیید ثبت‌نام و بازیابی رمز عبور امکان‌پذیر نیست.

### ۲-۳. ماژول گزارش‌گیری (Reporting)

- موجودیت‌ها و مخازن گزارش تعریف نشده‌اند؛
- هیچ گزارش عملیاتی (مدیریتی، عملکردی، مالی) تولید نمی‌شود؛
- داشبورد فعلی فقط نمای کلی محدودی ارائه می‌دهد.

### ۲-۴. ماژول سرشماری (Inventory)

- کنترلر REST عمومی برای ماژول سرشماری وجود ندارد (دریافت فقط از طریق میزبان API عامل‌ها انجام می‌شود)؛
- عمق داده سرشماری محدود به دسته‌های اصلی سخت‌افزار/نرم‌افزار است و زیرمجموعه‌های تخصصی‌تر هنوز پوشش داده نشده‌اند.

### ۲-۵. چارچوب افزونه (Plugins — بخش‌های به تعویق افتاده)

هسته چارچوب افزونه (بارگذاری ایزوله با AssemblyLoadContext، مهاجرت در شمای `plugins_{id}`، مدیریت چرخه حیات و رابط کاربری مدیریت افزونه‌ها) پیاده‌سازی شده است؛ موارد زیر عمداً به نسخه‌های بعدی موکول شده‌اند (شرح کامل در ADR-007):

- **بارگذاری پویای رابط کاربری افزونه (Module Federation)**: فیلد `remoteEntryUrl` مانیفست اعتبارسنجی (فقط http/https) و ذخیره می‌شود، اما اتصال `loadRemoteModule` در شل و بارگذاری Web Component افزونه هنوز انجام نشده است — فعلاً به‌صورت stub مستند شده است؛
- **فراخوانی `IPlugin.ConfigureApp`** به‌طور عمدی هرگز انجام نمی‌شود (خط لوله میزبان متعلق به ریشه ترکیب است — ADR-005)؛ متد روی اینترفیس برای نقطه توسعه آتی میزبان باقی مانده است؛
- امضای دیجیتال افزونه (Authenticode) پیاده‌سازی شده اما به‌صورت **اختیاری و خاموش** است؛ فعال‌سازی آن در محیط تولید نیازمند توزیع فهرست رد انگشت گواهی‌های مجاز است؛
- افزونه‌های مرجع نمونه برای نقش‌های اعلام‌شده (نوع دارایی با فیلدهای سفارشی، قواعد خودکار تیکت) هنوز ساخته نشده‌اند.

## ۳. رابط کاربری (Frontend)

ماژول‌های زیر دارای بک‌اند کامل‌تر هستند ولی **رابط کاربری آن‌ها هنوز ساخته نشده است**:

| ماژول | وضعیت بک‌اند | وضعیت UI |
|---|---|---|
| میز خدمت (تیکت‌ها) | پیاده‌سازی‌شده | ❌ ساخته نشده |
| مالی (قرارداد، بودجه، خرید) | پیاده‌سازی‌شده | ❌ ساخته نشده |
| دانش (مقالات) | پیاده‌سازی‌شده | ❌ ساخته نشده |
| نرم‌افزار و مجوزها | پیاده‌سازی‌شده | ❌ ساخته نشده |
| مدیریت کاربران/نقش‌ها | پیاده‌سازی‌شده | ❌ ساخته نشده (بخشی از API) |
| خودکارسازی | ناقص | ❌ ساخته نشده |
| اطلاع‌رسانی | ناقص | ❌ ساخته نشده |
| گزارش‌گیری | ناقص | ❌ ساخته نشده |

سایر موارد UI:

- رابط کاربری فعلی به زبان انگلیسی است؛ نسخه فارسی‌سازی کامل UI در برنامه کاری قرار دارد؛
- آزمون‌های خودکار فرانت‌اند (Karma/Jasmine) هنوز نوشته نشده‌اند (زیرساخت آماده است)؛
- نمودار شبکه (Network Map) و پنل رضایت‌سنجی تیکت به‌صورت ناقص/آغازین هستند.

## ۵. زیرساخت و استقرار

| مورد | وضعیت |
|---|---|
| Docker Compose تولید | ✔ آماده (PostgreSQL/Redis/RabbitMQ/دو میزبان/فرانت‌اند/نگینکس) |
| پوشش وورکرها در استقرار | ◐ فقط ۳ وورکر در Compose تعریف شده، در حالی که ۵ پروژه وورکر وجود دارد (CommandDispatch، Discovery، InventoryProcessor، RuleEvaluator و NotificationDispatcher نیاز به سرویس مستقل در Compose دارند) |
| HTTPS/TLS | ❌ نگینکس در پیکربندی فعلی فقط HTTP است؛ گواهی TLS و ریدایرکت HTTPS پیکربندی نشده |
| پایگاه داده | ◐ مکانیزم مهاجرت (EF Migrations) فقط برای ماژول دانش وجود دارد؛ مهاجرت یکپارچه برای سایر ماژول‌ها تهیه نشده |
| بکاپ و بازیابی | ❌ اسکریپت/برنامه منظم بکاپ تهیه نشده است |
| پایش و هشدار | ◐ Health Check و لاگ ساخت‌یافته فعال است؛ داشبورد پایش مرکزی و هشداردهی وجود ندارد |
| CI/CD | ❌ خط لوله ساخت و استقرار خودکار (مانند GitHub Actions) تعریف نشده است |
| مقیاس‌پذیری افقی | ◐ معماری آماده است ولی پیکربندی Load Balancer و اجرای چند نمونه مستقر نشده |

## ۸. جمع‌بندی

سامانه دارابان در نسخه فعلی، هسته اصلی حوزه ITSM/ITAM شامل هویت و دسترسی، مدیریت دارایی‌ها، میز خدمت، مالی، دانش، نرم‌افزار، کشف شبکه و سرشماری خودکار را پوشش می‌دهد. اولویت‌های توسعه آینده به ترتیب عبارت‌اند از:

1. تکمیل ماژول‌های اطلاع‌رسانی، گزارش‌گیری و خودکارسازی؛
2. توسعه رابط کاربری ماژول‌های میز خدمت، مالی، دانش و نرم‌افزار؛
3. تکمیل پیکربندی استقرار (وورکرها، HTTPS، مهاجرت‌های یکپارچه پایگاه داده، CI/CD)؛
4. تکمیل آزمون‌های فرانت‌اند، معماری و آزمون‌های بار/نفوذ؛
5. سخت‌سازی امنیتی (حذف کلید API انتقالی، امضای مانیفست استقرار، TLS).
