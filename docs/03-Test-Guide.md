## ۱. مقدمه

این مستند، راهنمای تست سامانه دارابان را ارائه می‌دهد و شامل استراتژی تست، انواع آزمون‌ها، نحوه اجرای آن‌ها و سناریوهای تست دستی کلیدی است. آزمون‌های خودکار این سامانه با چارچوب xUnit (بک‌اند) و Karma/Jasmine (فرانت‌اند) تهیه شده‌اند.

---

## ۲. استراتژی تست

استراتژی تست سامانه دارابان بر چهار لایه استوار است:

1. **تست واحد (Unit Test):** آزمون منطق کسب‌وکار سرویس‌های هر ماژول با جداکردن وابستگی‌ها (Moq)؛
2. **تست یکپارچه (Integration Test):** آزمون لایه داده و مخازن با پایگاه داده واقعی PostgreSQL در کانتینر (Testcontainers)؛
3. **تست معماری (Architecture Test):** بررسی قواعد لایه‌بندی و استقلال ماژول‌ها (NetArchTest)؛
4. **تست دستی (Manual/Smoke Test):** آزمون سناریوهای کاربری اصلی در محیط اجرایی.

---

## ۳. انواع آزمون‌ها و پوشش

### ۳-۱. تست واحد

تست‌های واحد برای هر ماژول دامنه در پوشه `tests/UnitTests` قرار دارند:

| پروژه تست | ماژول تحت پوشش |
|---|---|
| Daraban.Modules.Assets.Tests | مدیریت دارایی‌ها، تخصیص، چرخه حیات، مرجع‌ها، ورود/خروج انبوه |
| Daraban.Modules.ServiceDesk.Tests | میز خدمت، گردش کار تیکت، وظایف، الگوها |
| Daraban.Modules.Identity.Tests | احراز هویت، توکن‌ها، مجوزها، سرویس عامل‌ها |
| Daraban.Modules.Financial.Tests | بودجه، قرارداد، خرید، تأمین‌کننده، Infocom |
| Daraban.Modules.Knowledge.Tests | مقالات دانش، دسته‌ها، اعتبارسنجی، جستجو |
| Daraban.Modules.Software.Tests | محصولات، مجوزها، نصب نرم‌افزار |
| Daraban.Modules.Inventory.Tests | سرویس سرشماری |
| Daraban.Modules.Discovery.Tests | رمزنگاری اعتبارنامه‌ها، قوانین واردات |
| Daraban.Modules.Automation.Tests | بستر خودکارسازی |
| Daraban.Modules.Notifications.Tests | بستر اطلاع‌رسانی |
| Daraban.Modules.Reporting.Tests | بستر گزارش‌گیری |

نمونه‌های مهم سناریوهای تحت پوشش:

- چرخه کامل وضعیت تیکت (شامل وضعیت‌های نهایی و ممنوعیت انتقال از وضعیت‌های پایانی)؛
- محاسبه امتیاز خودکار تیکت (اولویت × تأثیر × فوریت)؛
- چرخه حیات دارایی و تاریخچه تخصیص؛
- جلوگیری از دریافت تکراری سرشماری (Idempotency)؛
- گردش توکن تازه‌سازی و ابطال توکن؛
- اعتبارسنجی ورودی‌ها (FluentValidation) در ثبت دارایی، تیکت و کاربر؛
- رمزنگاری و رمزگشایی اعتبارنامه‌های SNMP؛
- ترجمه کوئری‌های جستجوی دانش.

### ۳-۲. تست یکپارچه

برای آزمون‌های مرتبط با پایگاه داده از `Testcontainers.PostgreSql` استفاده می‌شود که یک نمونه PostgreSQL واقعی در کانتینر موقت ایجاد و پس از پایان آزمون حذف می‌شود. این آزمون‌ها صحت پیکربندی موجودیت‌ها، مخازن و رفتارسازی‌های پایگاه داده را بررسی می‌کنند.

### ۳-۳. تست معماری

پروژه `Daraban.Platform.ArchitectureTests` قواعد معماری زیر را مستند و بررسی می‌کند:

- لایه API نباید به‌طور مستقیم به لایه داده وابسته باشد؛
- ماژول‌ها نباید به سرویس‌ها یا لایه داده سایر ماژول‌ها ارجاع مستقیم داشته باشند (ارتباط فقط از طریق قراردادهای مشترک).

### ۳-۴. تست فرانت‌اند

زیرساخت آزمون فرانت‌اند (Karma + Jasmine) در پروژه Angular پیکربندی شده و از طریق `ng test` قابل اجراست. نوشتن موارد آزمون برای کامپوننت‌های کلیدی در برنامه کاری قرار دارد (جزئیات در مستند «قابلیت‌های پیاده‌سازی‌نشده»).

## ۴. نحوه اجرای آزمون‌ها

### ۴-۱. اجرای آزمون‌های بک‌اند

از ریشه پروژه:

```bash
dotnet test Daraban.Platform.sln
```

اجرای آزمون‌های یک ماژول خاص:

```bash
dotnet test tests/UnitTests/Daraban.Modules.Assets.Tests
```

توجه: برای آزمون‌های یکپارچه مبتنی بر Testcontainers، موتور Docker باید فعال باشد.

### ۴-۲. اجرای آزمون‌های فرانت‌اند

```bash
cd frontend
ng test
```

## ۵. سناریوهای تست دستی کلیدی (Smoke Test)

پس از استقرار سامانه، سناریوهای زیر به‌صورت دستی در محیط آزمایشی (یا تولید-پایلوت) اجرا می‌شوند:

| # | سناریو | مراحل | نتیجه مورد انتظار |
|---|---|---|---|
| ۱ | ثبت‌نام و ورود | ثبت‌نام کاربر جدید ← خروج ← ورود مجدد | ورود موفق و نمایش داشبورد |
| ۲ | ثبت دارایی | ثبت دارایی با نوع/مدل/مکان ← جستجوی آن | دارایی در فهرست با جزئیات صحیح نمایش داده شود |
| ۳ | تخصیص دارایی | تخصیص دارایی به کاربر ← مشاهده تاریخچه | وضعیت دارایی و تاریخچه تخصیص به‌روز شود |
| ۴ | ثبت و رسیدگی تیکت | ثبت تیکت ← قبول توسط کارشناس ← حل ← بستن | چرخه وضعیت‌ها در تاریخچه تیکت ثبت شود |
| ۵ | کشف شبکه | تعریف محدوده IP ← اجرای اسکن ← مشاهده نتایج | دستگاه‌های قابل دسترس در نتایج ظاهر شوند |
| ۶ | مدیریت عامل | ثبت/مشاهده عامل و بررسی آخرین تماس | وضعیت عامل (آنلاین/آفلاین) صحیح نمایش داده شود |
| ۷ | واردات انبوه دارایی | بارگذاری فایل اکسل نمونه ← بررسی نتیجه | دارایی‌ها با پیام موفقیت/خطا وارد شوند |
| ۸ | دسترسی غیرمجاز | تلاش برای دسترسی به مسیر بدون مجوز | پاسخ ۴۰۳/۴۰۱ و عدم نمایش داده |

## ۶. محیط‌های تست و داده

| محیط | شرح |
|---|---|
| توسعه (Development) | اجرای محلی با زیرساخت Docker (PostgreSQL/Redis/RabbitMQ) |
| آزمایش (Staging) | استقرار کامل Docker Compose با داده آزمایشی و کلید امضای JWT اختصاصی |
| تولید (Production) | استقرار نهایی با پیکربندی امن (رمزهای قوی، HTTPS) |

داده‌های آزمون‌های خودکار به‌صورت ایزوله (در حافظه یا کانتینر موقت) تولید می‌شوند و هیچ‌گونه وابستگی به داده تولید ندارند.

---

## ۷. محدودیت‌ها و برنامه آینده

- آزمون‌های معماری NetArchTest در نسخه فعلی به‌صورت قواعد مستند پیاده‌سازی شده‌اند و اتصال کامل آن‌ها به تحلیل اسمبلی‌ها در برنامه کاری است؛
- آزمون‌های خودکار فرانت‌اند هنوز نگارش نشده‌اند؛
- آزمون‌های بار (Load Test) و نفوذ (Penetration Test) در برنامه آینده سامانه قرار دارند.

> یادداشت: با توجه به اختیاری بودن این مستند، در صورت نیاز می‌توان بخش‌های ۵ و ۶ را پس از استقرار در محیط آزمایشی با نتایج واقعی به‌روزرسانی کرد.
